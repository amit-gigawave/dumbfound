The steps below stay as the recipe for future drops.

For each new work, follow "A 3D scan" in [adding-artworks.md](adding-artworks.md):
1. **Convert**: USD → GLB with the Blender 5.1 command in that guide (it keeps vertex colours and drops the see-through alpha), then Draco-compress. List the meshes in Blender first: some drops hold stacked duplicate copies.
2. **Check the model** (`npm run check-model`): opaque with back faces culled, correct winding, vertex colours present, no glass `transmission`. Find the straight-on `facing` from a 10° turntable sweep, never just 90° steps.
3. **Details only from a source**: the "Sculpted India (Digital)" sheet (column F; the source the user named) or the Artlogic "To be Scanned works" view, matched by photo. If unsure, leave title/year/medium/size blank. Never invent them. No title may say "Untitled": give a descriptive name, with a comment holding the source title.
4. **Set** `form` (`"head"`, `"figure"` or `"other"`) so it lands in the right group on the Artworks grid. Set `heightCm` only from real dimensions.
5. **Render**: `npm run ar-models -- <slug>` and `npm run thumbnails -- <slug>` (dev server running; load `/` once first so it is warm). Bump `?v=` whenever a thumbnail's picture changes.
6. **Light it**: give it a `look` (see to-do 2), then remake its thumbnail.
7. Commit each work on its own as Ayan Ali. To publish, push the branch to `origin` + `ayan` and merge it into each `main` (no force), only when asked.

## Good to know
- **Dev server**: `npx next dev --webpack -p 3000`. Turbopack crashes on this machine (`0xc0000142`, its PostCSS worker can't start). Its file watcher sometimes stops picking up edits. If a change doesn't show, restart the server. Stopping the background task can leave its `start-server.js` node process holding port 3000. Find that PID with `netstat -ano`, check its command line, and end only that process.
- **Testing 3D in headless Chrome**: software WebGL is slow, and screenshots of a live 3D canvas often time out. Check state through the page instead (canvas present, opacity, URL). Put a hard deadline in test scripts so a hung browser can't hang the run. The scratch test scripts were not kept in the repo.
- **Spotlight's 3D model** (`Live` in `Spotlight.tsx`) waits until the glide is idle before loading: loading a model freezes the page briefly, and mid-glide that made it stutter and split one trackpad flick into two steps.
- **React tree vs DOM**: drei's `<Html>` (the 3D loading spinner) is a separate React root, so React's `onMouseLeave` fires when the pointer moves onto it. True scale's `HoverZone` uses native `mouseenter`/`mouseleave` for that reason.
